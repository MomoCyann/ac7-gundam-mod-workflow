# 制作与排错

## 从模型到可运行基线

1. **建立对照。** 记录原游戏和参考 PAK 在机库、任务、速度变化和换武器时的表现。先检查目标机体的 Pawn、动画配置、骨架、武器组件、挂点与 PAK 挂载点。导出 PSK/PSA 给 Blender 核对。保留一个实际通过的 PAK 和它的 SHA-256。
2. **搭可编辑的模型。** 用装甲、连接件、发光件和武器分组装配。还原原网格的绑定姿态与机械铰点。按新的目标骨架绑权重。区分肩甲随手臂抬升和肩甲独立开合，给翼座与活动翼独立父级。需要镜像时以用户已调整的一侧为准，核对另一侧轴向、材质和挂点。
3. **完成静态闭环。** 在小范围先验证单位、轴向、骨骼顺序、UV、材质槽和法线。导出 FBX，用干净的 UE 4.18 工程 Cook，按目标内部路径组织生成的资产。柯西保留 `../../../Nimbus/Content/` 挂载点。以 UnrealPak 包装并验证，再用 UModel 读回。此时先跑机库和单人任务，确认模型可见、比例与贴图正确。

## 动画、灯光和武器

1. **姿态和驱动。** 冻结用户确认的 Blender 场景。核对 `PartsAnimationConfig`、`PlaneBodyConfig` 和 `x02s_Anim` 中速度、襟翼、横滚、俯仰、偏航、开火和武器选择驱动到的实际骨骼。将姿态烘焙到对应轨道。保证局部变换合成后，机体部件、喷口和发射位的世界位置正确。看开合先后能否让肩甲和尾翼避开穿模。
2. **武器过渡。** 先确认 SP1 的目标姿态在各速度下相同。进入时用实时普通姿态作为起点，退出时用当前速度对应普通姿态作为终点。用同一机体网格和双骨骼影响混合时，沿过渡采样，检查胳膊和腿甲有没有塌陷，核对喷口在两路驱动时都跟在正确部件上。
3. **自发光。** 在绑定后空间沿肩甲的斜面洞口测边并拟合平面灯片，按闭合和展开两种姿态验证。颜色图集、材质和发光遮罩都要核对。柯西使用 `Emissive_*` 路径和 MREC 蓝通道，灯片与机头眼睛可以使用不同的图集色块。给色块内的 UV 留边，再检查 Cook 后图集中实际采样的位置。
4. **武器改装。** 从已运行的组合核对 Pawn 武器类、发射网格及骨架、AnimBP、弹体移动组件与粒子依赖。首先只变更发射参数，接着添加或移动挂点。对每个挂点同时修改位置、朝向、绑定姿态与发射动画。在游戏里用普通武器、SP1 和其他武器槽分别验证机库和任务。

## 症状对应的第一轮检查

| 实际症状 | 优先检查 |
| --- | --- |
| 普通形态不可见，SP1 可见 | 检查普通与特武的骨骼缩放、Pawn 组件引用、包优先级与覆盖关系。分别装基线和单项改动测试。 |
| 网格爆开、贴图拉伸 | 先查骨序、分段骨骼映射与轨道流，再检查 UV。UE 4.18 的 Constant Key Lerp 轨道流按每骨 T/R/S 顺序读取。手工插轨时按运行时顺序重新写流与偏移。柯西曾出现 UModel 能解出、实机仍撕裂的情况。 |
| 切 SP1 有重影或肩甲突然收起 | 检查是否同时绘制两套机体。核对过渡起、终点使用的是实时普通姿态还是固定的站姿。分别从巡航和高速进入与退出，再保持 SP1 改变速度。 |
| 贴图变亮但眼睛不发光 | 检查网格材质槽、发光材质、图集 UV 和 Cook 后的遮罩，而后进游戏看眼部表现。 |
| 导弹包在机库加载时崩溃 | 暂时停用武器覆盖包，确认主包可用。回到已运行的 Pawn、熟悉的武器类、移动组件、发射网格和 AnimBP 组合，每次变更一个项目。 |

## 归档和发布

用 `UnrealPak -Test` 检查两个成品 PAK，回读骨架、动画、材质和武器配置。实机检查机库、普通与特武、巡航和高速双向过渡、SP1 内变速、四向摇杆、灯光喷焰和发射。离线验证与实机结果分别写明。保存工作源、生成输入、工具版本、包名与优先级，以及最后能回退的本地版本。发布范围以实际素材许可为准。
